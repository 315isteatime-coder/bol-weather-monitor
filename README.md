# KIIKII 内部工具

珠海十字门 C1017 店内部用，手机优先。线上：**ieclong.com**

## 四个页
- **今日** 本月达成率、我的私佣公佣实收、本周挂单条形图、假期奖励进度
- **佣金** 填店铺营业额 + 我的挂单额 + 工时，即出私佣／公佣／大单奖／实收
- **排班** 一周视图，店长排班、店员报班，接后端全店共用
- **手册** 营业时间、POS 红线、每单流程、特殊情况、排班规则、工资算法、找谁

界面文字一律用普通话书面中文（简体），不用粤语口语 —— 员工在珠海。

## 规则真源
佣金规则来自 KIIKII repo `十字门C1017/开业筹备/珠海店-人员编制与薪酬提成方案-v1.md` §5（v6 定稿 2026-09-07）。
**改规则先改那份文件，再改 `app.js` 顶部常数。** 这里只是执行，不是真源。

摘要：
- 私佣 ＝ 当档费率（封顶 3%）× 个人目标以内 ＋ 6% × 超出部分
  个人目标 ＝ 月目标 ÷ 全职人数，兼职按工时折算
- 公佣 ＝ 当档费率（达标 4%）× 全店营业额，店长先分 20%，其余按上班时间摊分
- 大单奖 满 800／1400／2400 加 10／30／50，取最高档
- 全店达成 120% → 每人加一天带薪假
- 开业头三个月费率封顶 2%，6% 不开放

## 技术取舍
**零外部请求。** 用户在珠海，Google Fonts 被墙、unpkg／jsdelivr 不稳，
而本 repo 2026-07-11 那条 commit 已经证实 esm.sh 动态 import 会令手机提交失败。
所以：系统字体、无图示库、无 CDN、无框架。三个文件就是全部。

## 已知限制
- **排班已接后端**（Supabase），全店共用同一份，店长排完员工即刻见到。
- **佣金页同今日页仍然只存 localStorage**，每部手机一份。
- 佣金页算的是估算，发薪以店长实际结算为准。

## 排班后端

Supabase project `plan-b`（`otyyndkystpjfdhujfbp`），与 bestplan 共用同一个 database，
全部对象用 `kk_` 前缀，将来可整批 migrate 走。

| 对象 | 用途 |
|---|---|
| `kk_staff` | 名单、角色、PIN、月工时 |
| `kk_sessions` | 登入 token，60 日过期 |
| `kk_shifts` | 班次，`state` 为 `requested`（员工报班）或 `assigned`（店长批咗） |

**安全**：三张表零 anon policy，直接读表返 401。所有读写行 SECURITY DEFINER RPC，
每个都要 token；`kk_assign` 额外检查 `role='manager'`。已实测：
员工直接 call `kk_assign` 返 `manager_only`，乱 token 返 `not_signed_in`。

**改名单／改 PIN**：去 Supabase 改 `kk_staff`。预设 PIN 店长 1017，
资深 2201／内容 2202／兼职 A 2203／兼职 B 2204 —— **上线后叫大家改，或者你逐个重设。**
